## 摘要
机器人足球是多智能体强化学习的一个具有挑战性的测试平台，因为它结合了部分可观测性、合作与对抗交互、稀疏奖励和长时序战术行为。RoboCup 2D足球仿真（RCSS2D）提供了一个成熟的机器人足球平台，但其面向竞赛的服务器-客户端架构难以直接与现代基于Python的多智能体强化学习工作流程结合使用。我们介绍了R2D-RL，这是一个强化学习环境，通过共享内存通信和周期级同步将RCSS2D和基于HELIOS的球员客户端连接到Python多智能体强化学习接口。R2D-RL支持全场和基于场景的训练，具有可配置的对手、基本离散和混合参数化动作空间、动作掩码、基于预期控球值（EPV）的奖励塑造以及并行执行。我们提供了前场进球场景和一个11对11全场基准，以及基线结果。

## Abstract
Robot soccer is a challenging testbed for multi-agent reinforcement learning because it combines partial observability, cooperative and adversarial interaction, sparse rewards, and long-horizon tactical behavior. RoboCup 2D Soccer Simulation (RCSS2D) provides a mature robot-soccer platform, but its competition-oriented server-client architecture is difficult to use directly with modern Python-based MARL workflows. We introduce R2D-RL, a reinforcement learning environment that connects RCSS2D and HELIOS-based player clients to a Python MARL interface through shared-memory communication and cycle-level synchronization. R2D-RL supports full-field and scenario-based training with configurable opponents, Base discrete and Hybrid parameterized action spaces, action masks, expected possession value (EPV)-based reward shaping, and parallel execution. We provide front-goal scenarios and an 11-vs-11 full-field benchmark, together with baseline results.

## 2. 论文提出的方法论

### 2.1 系统架构与同步通信
- **基础思路**：保留RCSS2D服务器和修改后的HELIOS球员客户端、教练、训练器，通过共享内存与Python环境通信，并强制执行周期级的同步。
- **通信协议**：采用共享内存中的序列计数器机制，将球员的观测发布、动作指派、动作消费三个环节解耦：
  - 每个被控球员在`play_on`阶段将观测和动作掩码写入共享内存并递增`obs_seq`；
  - Python环境等待所有被控球员满足`obs_seq > act_seq`后，读取观测并返回给学习算法；
  - 算法输出联合动作，环境将动作写入相应球员缓冲区并设置`act_seq`；
  - 球员读取动作并执行，随后更新`done_seq`，环境等待`done_seq == act_seq`以确认动作已被消费。
- **结果**：每一步环境交互精确对应一次RCSS2D的`play_on`决策点，教练侧的全局状态与球员侧观测严格对齐，实现了从竞赛流程到步进式MARL交互的转换。

### 2.2 环境语义设计
- **游戏模式处理**：仅在`play_on`（开放比赛）阶段暴露策略决策，其余定位球、开球等阶段由RCSS2D规则和HELIOS回退行为处理，不计入episode步数。
- **状态与观测**：
  - 集中式状态：教练提供的136维向量（球与22名球员的位置、速度等）。
  - 局部观测：每名被控球员97维向量（自身状态、球信息、队友/对手位置速度、比赛模式等）。
- **动作空间**：
  - **Base离散动作空间**：基于HELIOS的高层语义行为（射门、传球、盘带、移动等），共19种离散选项，真实的低层控制由HELIOS内部生成。
  - **Hybrid参数化动作空间**：直接暴露低层体指令（转身、冲刺、踢球、扑救），每个指令为离散ID搭配连续参数，如踢球的方向和力量。
- **动作掩码**：根据执行条件动态屏蔽不可行动作（例如只有可踢球时才允许射门；射门可用时优先屏蔽其他动作）。这大幅降低了探索负担。
- **终止条件**：可配置的终止信号，包括进球、出界、控球丢失、超时（按`play_on`步数）。
- **奖励函数**：团队级得分奖励（+1/−1）与可选的基于最大预期控球值（MaxEPV）的奖励塑造。EPV网格记录球场不同区域的进球期望，奖励定义为当前运行最大EPV的正向增量，仅在己方有球员可踢球时更新，鼓励控球向更高价值区域推进。
- **场景重置**：通过训练器直接重置服务器中球和球员的位置、方向、速度，避免重启整个服务器，显著加快训练速度。

## 3. 实验设计

### 3.1 实验场景与分组
- **并行吞吐量测试**：在32逻辑CPU的机器上测量随机策略下R2D‑RL环境步每秒的吞吐量，比较Base和Hybrid动作空间下随并行环境数增加的表现。
- **前场进球场景（Front-goal scenarios）**：五个从简单到复杂、共享进攻方向（向右）的控球进攻任务。

  - 多攻击者场景：**Support Option**（有支援队友）、**Passing Lane**（有传球路线选择）、**Compact Defense**（面对密集防守的多攻击者协同），逐步增加团队协作和决策难度。
- **11‑v‑11全场基准**：完整的RoboCup 2D比赛设定，被控球队为左队，对手使用内置AI。记录目标差与最大EPV提升作为评估指标。

### 3.2 对比方法
- 针对Base离散动作空间：**MAPPO**（多智能体PPO）和**QMIX**（值分解）。

## 6. 论文的主要结论与发现

- **环境可用性**：R2D‑RL成功将RCSS2D转化为步进式MARL环境，支持并行采样和全生命周期管理，吞吐量可达每日数千万环境步。
- **渐进式任务难度**：前场场景的进球率随任务复杂度上升而明显下降，验证了场景设计的合理性，并为算法评价提供了难度梯度。
- **组件有效性**：
  - **动作掩码**：在Blocked Shot等有防守压力的任务中，对QMIX等算法至关重要，掩码关闭时性能骤降。
  - **MaxEPV奖励**：在复杂多攻击者场景（如Compact Defense）中，结合掩码是唯一能产生显著非零成绩的配置。
- **算法表现**：MAPPO在多数任务中最稳定；QMIX成绩受种子影响大；ParaDQN在简单场景可训练，但在多攻击者和全场中几乎完全失败，表明Hybrid参数化接口在复杂足球任务中极难学习。
- **全场初步结果**：在30M步训练后，MAPPO在目标差与EPV提升上优于其他基线，但所有方法仍处于较弱水平，说明长视野全力比赛需要更大的训练规模和更复杂的训练策略。

## 7. 优点

- **保留原生生态**：不重新发明模拟器，而是基于成熟RCSS2D和HELIOS，使研究可直接受益于已有的比赛规则、物理引擎和行为库。
- **训练就绪接口**：提供标准MARL环境（集中式状态、局部观测、动作掩码、终止条件、重置控制器），大幅降低RoboCup领域的学习门槛。
- **丰富的决策接口**：同时提供离散高层语义动作和混合参数化动作空间，可支持不同抽象层级的研究。
- **有力的环境组件**：内置基于EPV的奖励塑造和来自HELIOS可执行性检查的动作掩码，这些在实际训练中表现出重要的辅助作用。

## 8. 不足与局限

- **对手与训练策略单一**：实验仅用固定内置AI作对手，缺乏自对弈或多样化对手池，无法考察策略的泛化与鲁棒性；也未探索演示学习、课程学习等高级训练技术。
- **训练预算有限**：全场基准的训练步数（30M）对于11人制足球明显不足，结论仅反映早期训练表现，不能代表算法的最终潜力。

- **模式覆盖不全**：策略仅控制`play_on`阶段，忽略开球、任意球、球门球等定位球战术，这部分在实际比赛中占比可观。

- **算力报告缺失**：训练所用GPU等硬件资源及实际耗时不详，不利于外部复现和对训练成本的预估。
