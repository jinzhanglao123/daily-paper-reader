## 摘要
LLM向工具赋能智能体的演进带来了与真实世界执行相关的新一类安全挑战，而非单纯的文本生成。现有对齐方法通常依赖粗略的拒绝信号或静态监督，难以在多样化的智能体风险中平衡安全性与有用的工具执行。我们提出了RUBAS，一个基于评分细则的智能体安全强化学习框架。RUBAS将智能体行为分解为四个维度：工具使用安全性、参数安全性、响应安全性和有用性。这些结构化的评分细则在完整的智能体轨迹上提供了细粒度和可解释的奖励，使强化学习能够优化安全的工具使用，同时保持任务完成度。跨多个智能体安全基准和模型的广泛实验表明，RUBAS相比标准对齐基线提高了安全性，减少了基于工具的幻觉，并保持了有竞争力的效用。我们的结果表明，多维评分细则奖励为在安全关键的工具使用场景中对齐LLM智能体提供了有效的训练信号。

## Abstract
The evolution of LLMs into tool-enabled agents creates a new class of safety challenges associated with real-world execution rather than simple text generation. Existing alignment methods often rely on coarse refusal signals or static supervision, making it difficult to balance safety with useful tool execution across diverse agentic risks. We introduce RUBAS, a rubric-based reinforcement learning framework for agent safety. RUBAS decomposes agent behavior into four dimensions: tool-use safety, argument safety, response safety, and helpfulness. These structured rubrics provide fine-grained and interpretable rewards over complete agent trajectories, enabling reinforcement learning to optimize safe tool use while preserving task completion. Extensive experiments across multiple agent safety benchmarks and models show that RUBAS improves safety over standard alignment baselines, reduces tool-grounded hallucinations, and maintains competitive utility. Our results suggest that multi-dimensional rubric rewards provide an effective training signal for aligning LLM agents in safety-critical tool-use settings.

## 1. 研究背景与核心问题
*   **问题背景**：大型语言模型（LLM）正从单纯的文本生成器演变为能够通过外部工具调用（如 Web 搜索、API 交互）在真实环境中执行动作的智能体。这种扩展带来了全新的安全挑战，不仅限于文本内容安全，还涵盖了完整的行动轨迹（工具选择、参数传入、输出响应）与环境交互的风险。
*   **现有方法局限**：
    *   **监督微调（SFT）**：主要模仿训练数据中的安全行为模式，难以内化安全轨迹的原则，导致泛化能力差，常停留在表层对齐。
    *   **传统强化学习（RL）**：常使用二元的或稀疏的奖励信号，难以捕捉在复杂环境中兼顾安全性与有用性的微妙权衡，容易诱发过于保守的一刀切式拒绝。
*   **核心问题与动机**：如何在多功能、多轮次的工具使用场景中，对 LLM 智能体进行高效的安全对齐。关键是要设计出一种既能提供细粒度可解释反馈，又能平衡不同维度（安全性与有用性）的训练信号，实现深层次的原则内化，而非表面行为模仿。

## 2. 方法论
### 核心思想
提出 **RUBAS (Rubric-Based Reinforcement Learning for Agent Safety)**，将“安全且有用的智能体行为”分解为一组结构化的、可验证的子目标。利用 **“验证比生成更容易”** 的不对称性，通过构建一个多维度的评分细则（Rubric），对智能体完整轨迹进行细粒度的评价，并将定性要求转化为稠密的标量奖励信号，驱动强化学习优化。

### 关键技术细节
*   **四维评分维度设计**：RUBAS 将智能体行为评价分解为四个可验证的维度 \( R=\{r_{tool}, r_{arg}, r_{res}, r_{help}\} \)：
    1.  **工具使用安全性 (Tool-use Safety)**：评估是否调用了未授权或危险的工具，以及工具调用的逻辑顺序是否正确。
    2.  **参数安全性 (Argument Safety)**：确保传递给工具的参数不包含恶意、敏感或超范围的数据。
    3.  **响应安全性 (Response Safety)**：评估最终返回给用户的文本内容是否安全，特别是在工具返回错误或不安全信息时。
    4.  **有用性 (Helpfulness)**：在请求合法且安全合规的前提下，评估任务完成的程度和质量。
*   **评分细则构建与奖励函数**：
    *   对于每个维度 \( r_i \)，设定一组二元可验证标准 \( \{c_{i,1}, c_{i,2}, ...\} \)（如“是否调用了必调工具”、“参数是否匹配禁止正则”），这些标准由大模型（如 GPT-5.1）根据具体任务场景自动生成，并大多通过程序化检查器进行确定性验证（唯一的例外是“拒绝判断”标准，使用了一个分类器模型 Qwen3Guard-Gen-8B）。
    *   **奖励计算**：总奖励是各维度得分的加权聚合。
        \[
        R_{\text{rubric}}(\tau|x,R) = \frac{\sum_{i=1}^{|R|} w_i \cdot r_i(\tau|x)}{\sum_{i=1}^{|R|} w_i}
        \]
        其中每个维度得分 \( r_i \) 又是其下所有标准得分的归一化加权平均。
    *   **额外奖励信号**：为了保障训练稳定性，加入了完整性奖励 \( R_c(\tau) \)（达到终止条件的轨迹才有效）和推理奖励 \( R_r(\tau) \)（防止模型省略思维链以投机取巧）。
*   **训练流程**：
    1.  **数据构建**：基于 10 大风险类别和 6 大风险模式的双层分类体系，结合从多个基准中收集的 805 种工具元数据，利用生成式大模型（GPT-5.1）合成包含**有害 (Harmful)、敏感 (Sensitive)、良性 (Benign)** 三类场景的 prompt 与环境配置。同时为每条数据生成专用的评分细则。
    2.  **强化学习优化**：采用**群体相对策略优化 (GRPO)** 算法进行在策略（on-policy）训练。模型为每个 prompt 采样多条完整轨迹，根据实例化评分细则计算标量奖励，并利用组内相对优势对策略进行更新。

## 3. 实验设计
*   **数据集与基准**：
    *   **训练集**：自建的 RUBAS 训练数据，包含 2353 个实例（2000 有害、235 敏感、118 良性）。
    *   **安全评测基准**：
        *   **AgentSafetyBench (ASB)**：评估 10 类系统性安全失败。
        *   **InjecAgent (Injec)**：评测间接 prompt 注入攻击。
        *   **AgentHarm (AHarm)**：衡量在明确恶意直接 prompt 下的合规程度。
        *   **AgentSecurityBench (ASecBench)**：在对抗环境下测试智能体鲁棒性。
    *   **效用与幻觉评测基准**：
        *   **BFCL**：评估函数调用基础能力（工具使用效用）。
        *   **ToolBeHonest (TBH)**：评测工具使用的幻觉程度。
*   **对比方法**：
    *   **Rule (规则基线)**：基于 Sha 等人设计的二元规则奖励（如是否调用工具、是否在安全工具集内、是否拒绝）。
    *   **GuardModel (守卫模型基线)**：使用 Qwen3Guard-Gen-8B 作为外部安全判断器，输出二元安全分数作为奖励。
    *   **DPO (直接偏好优化基线)**：利用 RUBAS 奖励采样的偏好对进行离线偏好优化。
    *   **SFT (监督微调基线)**：在筛选后的安全、高质量轨迹上进行微调。
    *   **基础模型**：主要基于 Qwen3-8B、Qwen3-14B 和 GLM-4.7-Flash（30B 总参，3B 激活，MoE 架构）进行训练和评测。

## 4. 资源与算力
*   **硬件**：所有训练均在 **8 块 NVIDIA A800 GPU** 上进行。GRPO 训练时，其中 4 块用于推理，4 块用于优化。
*   **训练时长**：对于 Qwen3-8B，一次完整的 GRPO 训练运行（RUBAS、Rule、GuardModel）耗时约 **3.5 小时**。DPO 和 SFT 的训练各耗时约 **1 小时**。
*   **精度与配置**：采用 **BF16 全参数更新**，GRPO 各组每 prompt 采样 8 条回复，学习率 \(8 \times 10^{-6}\)，batch size 32，多轮交互上限为 4 轮，共训练 3 个 epoch。

## 5. 实验数量与充分性
*   **实验规模**：论文进行了系统而全面的实验。
    *   **主实验对比**：涉及 **3个基础模型**（含 2个密集模型、1个 MoE 模型）和 **5种方法**（含基线），在 **4个安全基准** 和 **2个效用/幻觉基准** 上进行评估。
    *   **消融实验**：
        1.  对比了**维度权重策略**（自动生成 vs. 固定权重）。
        2.  进行了**维度移除消融**：分别移除四个评分维度中的一个，观察对安全性和效用性的影响。
    *   **可靠性验证**：通过**跨模型一致性**、**人类对齐度**（加权人类参考平均绝对误差 W-HMAE）、**模型内部一致性**（加权内部平均绝对误差 W-IMAE）三方面，对 GPT-5.1 生成的评分细则进行可靠性验证。
    *   **案例研究**：展示了在高风险工具使用和对不可信工具输出等场景下，RUBAS 与其他基线的行为差异。
*   **评价**：实验设计非常充分、客观且公平。所使用的基准均为公开标准，对比方法涵盖了从 SFT 到 RL 的主流技术路线，消融实验深入剖析了框架各组件的独立作用，可靠性分析严谨地论证了基于自动评分细则训练的可行性。

## 6. 主要结论与发现
*   **显著的安全-效用平衡**：RUBAS 在三个模型上均实现了最好的或最具竞争力的安全-效用权衡。例如，在 Qwen3-8B 上，RUBAS 将平均风险分数从 52.7% 大幅降至 15.9%，且 BFCL 效用得分为 79.5%，远超所有基线。
*   **评分细则与在线 RL 必不可少**：
    *   粗粒度奖励（Rule, GuardModel）监督信号不足，会导致模型在安全约束上表现不佳或在某些模型（如 GLM）上直接退化。
    *   离线训练方法（SFT, DPO）对未见过的威胁泛化能力差（例如 SFT 反而增加了间接注入攻击成功率），且 DPO 可能导致效用崩溃。
*   **增强幻觉抵抗**：RUBAS 在所有模型上都取得了最高的幻觉分数（TBH 分数）。这说明其评分细则鼓励了对工具参数和最终响应更审慎的“对地验证”（grounding）过程，而非简单地拒绝。
*   **各评分维度作用分明**：消融实验证明四大维度不可互换：移除响应安全性维度最伤安全性；移除工具使用安全性维度表明环境交互的监督不可或缺；移除参数安全性维度会提升指标安全性但降低效用（暴露安全-效用权衡）；移除有用性维度则导致过度拒绝和效用下降。

## 7. 优点与亮点
*   **多维、可解释的奖励范式**：将复杂的智能体安全对齐问题分解为工具、参数、响应、效用四个透明且可验证的维度，比二元拒绝对齐更精细，提升了可解释性。
*   **“难生成、易验证”的成功应用**：利用 LLM 按模板自动生成针对具体任务场景的评分细则，将繁琐的定性评估转化为可扩展的标量奖励，思路巧妙且有效。
*   **问题场景的全面覆盖**：通过“风险类别+风险模式”的双层分类体系合成训练数据，系统性地覆盖了用户指令、工具执行、环境反馈三个风险来源，训练出的智能体不仅拒绝恶意请求，也能处理敏感上下文和对不可信工具输出进行验证。
*   **坚实的实验验证**：在多个主流基准和不同架构的模型上进行评估，并通过详尽的消融实验和可靠性分析，令人信服地证明了方法各组件的必要性和奖励设计的一致性。

## 8. 不足与局限
*   **合成数据偏差**：训练数据主要为合成数据，可能无法完全覆盖真实部署中的模糊用户意图、外部状态变化、领域特殊政策等情景。
*   **依赖强生成器**：评分细则的质量高度依赖于生成其的 LLM（如 GPT-5.1）的能力和偏见，存在生成不合理或不准确规则的风险。
*   **模型架构覆盖有限**：实验主要针对“思考模式”（Thinking-mode）的模型，未探讨在不输出思维链或思维链不可分离的模型上的表现。MoE 架构模型（GLM）上的安全提升幅度相对较小，表现出对模型架构的敏感性。
*   **非完全安全方案**：RUBAS 并非万无一失，对存在该训练分类体系之外的新型对抗性攻击可能仍会失效，部署中仍需结合运行时监控、人类批准等保护措施。
