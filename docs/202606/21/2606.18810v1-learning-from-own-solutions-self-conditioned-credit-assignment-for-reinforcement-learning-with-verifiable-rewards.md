## 摘要
基于可验证奖励的强化学习（RLVR）在训练大语言模型进行推理任务方面取得了重大进展，但像GRPO这样的代表性方法对所有标记赋予统一的信用，导致常规标记浪费梯度，而关键推理步骤的信用不足。现有的标记级信用分配方法需要超出模型自身生成结果之外的资源。GRPO的变体依赖于过程奖励模型或真实答案。知识蒸馏通过逐标记散度分配信用，但需要外部教师（On-Policy Distillation）或特权信息（On-Policy Self Distillation）。然而，这些依赖限制了在纯RLVR环境下的适用性。我们观察到，以模型自身的已验证轨迹为条件进行调节，会在原始分布和条件分布之间产生可测量的逐标记KL散度，并证明当存在多个已验证轨迹时，从由已验证轨迹构建的自教师中蒸馏会导致不可行的加权平均解。我们提出了SC-GRPO（自条件GRPO），它使用前述KL散度作为GRPO梯度的乘法权重。在涵盖数学、代码和智能体任务的五个基准测试中，SC-GRPO始终比GRPO性能提升8.1%，比DAPO提升5.9%，且具有更强的分布外（OOD）性能。此外，SC-GRPO的性能优于OPD。

## Abstract
Reinforcement learning with verifiable rewards (RLVR) has driven substantial progress in training LLMs for reasoning tasks, but representative methods such as GRPO assign uniform credit across all tokens, wasting gradient on routine tokens while under-crediting pivotal reasoning steps. Existing token-level credit assignment methods require resources beyond the model's own rollouts. GRPO variants rely on process reward models or ground-truth answers. Knowledge distillation assigns credit through per-token divergence but requires external teachers (On-Policy Distillation) or privileged information (On-Policy Self Distillation). However, these dependencies limit applicability in the pure RLVR setting. We observe that conditioning the model on its own verified trajectories induces a measurable per-token KL divergence between the original and conditioned distributions, and prove that distilling from a self-teacher constructed by verified trajectories leads to infeasible weighted-average solutions when multiple verified trajectories exist. We propose SC-GRPO (Self-Conditioned GRPO), which uses KL divergence mentioned before as a multiplicative weight on GRPO gradients. Across five benchmarks spanning math, code, and agentic tasks, SC-GRPO consistently outperforms 8.1% over GRPO and 5.9% over DAPO with stronger OOD performance. Moreover, SC-GRPO achieves higher performance than OPD.

## 1. 核心问题与整体含义
- **研究动机**：在 RLVR（例如 GRPO）训练 LLM 推理时，现有方法对所有 token 分配统一的序列级优势信号，造成梯度在常规 token 上浪费，而关键推理步骤得不到充分更新。
- **核心问题**：如何在 **纯 RLVR 设置**（仅有二元验证器，无外部教师、过程奖励模型或 ground-truth）中实现 **token 级自适应信用分配**。
- **整体含义**：通过 **以模型自己的已验证轨迹为条件**，观察 token 级分布偏移，得到一个自适应的信用分配信号，从而在不依赖外部资源的情况下提升训练效果。

## 2. 方法论
### 2.1 核心思想
- 利用模型自身已验证的轨迹作为 context，构建 **自条件教师**（self-conditioned teacher），计算教师分布与原始学生分布之间的 **逐 token KL 散度**。
- 将该 KL 散度用作 **GRPO 梯度的乘法权重**，而非额外的蒸馏损失。权重方向由奖励决定，强度由 KL 决定。
- 当多组相同 query 的 rollout 中存在部分正确样本时，用一条正确轨迹作为 context；当全部错误时，用一条随机轨迹作为 reference 获取“多样性信号”，用于探索。

### 2.2 关键技术与算法流程
- **教师构建**：对于学生 rollout 中的前缀 \(s_{i,t}=(x, o_{i,<t})\)，将一条已验证轨迹 \(\tau\) 插入教师 prompt 中，得到教师分布 \(\tilde{\pi}_\theta(\cdot|s_{i,t},\tau)\)，并 stop gradient。
- **KL 权重**：计算教师到学生的前向 KL 散度 \(D_{i,t}\)，然后通过映射 \(f(D_{i,t}) = D_{i,t}/(D_{i,t}+c)\) 得到 bounded 权重（其中 \(c\) 自适应选取为当前 batch 中 token KL 的 75 分位数，且不低于 \(10^{-4}\)）。低 KL token 被降权，高 KL token 保留。
- **分组路由**：
  - **部分正确组**（\(2 \le n_c < G\)）：对每个 rollout 选择一个正确的轨迹作为 teacher，使用 GRPO 的原始优势 \(\hat{A}_i\)。
  - **全错组**（\(n_c=0\)）：随机选一个 rollout 作为 reference，计算学生对 reference 的 KL 权重平均值作为多样性得分 \(s_i\)，再组内标准化得到伪优势 \(\hat{A}^{\text{div}}_i\)，并乘以系数 \(\alpha\) 作为探索信号。
  - 其他情况（\(n_c=1\) 或 \(n_c=G\)）：退化为标准 GRPO。
- **最终目标**：带权重的 GRPO 目标，\(f(D_{i,t})\) 对称地乘在正确和错误 rollout 的梯度上，不区分优势符号。

### 2.3 为何自蒸馏失败（理论基础）
- 证明在 RLVR 设置下，若将已验证轨迹直接作为 OPSD 的蒸馏目标，无论是前向 KL 还是反向 KL，优化得到的学生分布都会收敛到 **多个自条件教师的加权平均**（算术平均或几何平均）。
- 这种平均分布（i）不对应任何单一可行轨迹；（ii）对所有前缀同等加权，忽略了教师间的分歧；（iii）传播了已验证轨迹中可能包含的冗余、偶然步骤。因此，直接蒸馏必失败。

## 3. 实验设计
- **数据集与场景**：
  - 数学推理：DAPO-Math-17k 训练，AIME 2024 & 2025 评估。
  - 代码生成：LiveCodeBench v6（LCB），一半单元测试用于训练，另一半评估。
  - 多轮智能体交互：AppWorld（官方训练/测试分割）、WebShop（从训练分割随机取 2400 条）。
- **评价指标**：Avg@8（8 个样本的平均奖励）、Pass@8（8 个样本中至少一次正确的比例）。
- **基线方法**：
  - 强化学习：GRPO、DAPO、REINFORCE++
  - 外部教师 OPSD：用三种不同质量的外部 LLM（MiniMax-M2.7、DeepSeekv4-Pro、Oracle）提供演示轨迹，进行策略上的自蒸馏。
- 所有实验均基于同一基座模型 Qwen3-8B（thinking 关闭），共享相同的训练数据、rollout 数量和训练步长。

## 4. 资源与算力
- **实验环境**：8 节点集群，每节点 8 块 NVIDIA A100 80GB GPU，CPU 为 144 核 AMD EPYC 7713，960 GB 内存。
- **模型尺度**：仅测试 8B 参数模型，最大响应长度 12288 tokens。
- **训练超参数**：学习率 \(1\times10^{-6}\)，每组 8 个 rollout，每次更新 8 个 prompt（batch size 8），训练步数因任务而异（AIME 500 步，LCB 320 步，AppWorld 110 步，WebShop 300 步）。
- **计算开销**：SC‑GRPO 相比 GRPO 仅增加一次 teacher 前向传播，actor 更新时间增加 37%–51%，但端到端步时间仅增加 2%–13%，因 rollout 生成占主导。

## 5. 实验数量与充分性
- **主要对比**：在 **5 个基准** 上比较了 RL 基线（3 种）和 OPSD 基线（3 种），共 6 种方法对比，每个任务汇报 Avg@8 和 Pass@8。

  - 分组路由：对比仅部分正确组、部分+全错组、任意部分组、全部正确组等 5 种配置。
  - KL 阈值 \(c\)：比较自适应 p75、固定 \(10^{-4}\)、自适应 p50。
  - 多样性系数 \(\alpha\)：比较 0.1（最佳）与 0.2。

## 6. 主要结论与发现
- SC‑GRPO 在 5 个基准上全面超越基线：平均 **Avg@8 提升 8.1% (vs GRPO)**，5.9% (vs DAPO)；Pass@8 提升 8.9%。
- 在长序列多轮智能体任务上提升尤其显著，说明 token 级信用分配在长 horizon 任务上更有价值。
- 将 KL 作为权重 **远优于** 作为额外蒸馏损失，后者在实验中均未超越 GRPO，且理论上会导致不可行的加权平均分布。
- 外部教师 OPSD 不仅不能稳定提升，甚至可能低于基座模型，进一步印证了纯 RLVR 中依赖外部演示的不稳定性。
- SC‑GRPO 能保持更高的策略熵，维持探索能力，且在分布外测试中优势可迁移。

## 7. 优点
- **无需外部资源**：完全利用模型自身的 rollout 和二元验证器，适合纯 RLVR 场景。
- **简单高效的信用分配**：将 KL 散度作为乘法权重，不影响优势方向，仅调节强度，避免了蒸馏中分布平均的问题。
- **自适应阈值设计**：利用 batch 级别的 75 分位数和地板值，无需针对不同任务手动调参。
- **全面的分组处理**：针对部分正确和全错组分别设计机制，充分利用了训练数据及梯度信号。
- **计算开销低**：仅增加一次 teacher 前向，end-to-end 时间增额极小。
- **理论支撑**：从数学上证明了直接自蒸馏的不可行性，为方法设计提供了理论依据。

## 8. 不足与局限
- **模型规模有限**：仅在 8B 参数模型上验证，更大规模模型的效果尚未探索。
- **响应长度限制**：最大 12288 tokens，对更长序列的适用性未知。
- **扩展推理模式未测试**：仅使用 thinking 关闭的标准模式，未测试 chain-of-thought 等扩展推理形式。
- **任务类型**：虽覆盖数学、代码和简单智能体，但更复杂的交互、多模态等场景未涉及。
- **多样性信号的鲁棒性**：全错组的探索信号建立在“随机 reference”上，可能不够精准，需要系数 \(\alpha\) 小心调节（0.1 最佳，0.2 退化）。
- **KL 权重映射**：虽然自适应，但 75 分位数假设可能在某些极端稀疏的分布中失效，需要硬性地板值作为保护。
