## 摘要
判断一条轨迹是否真正完成了其指令，决定了我们如何衡量计算机使用智能体在长周期图形用户界面任务上的表现，以及如何用强化学习来训练它们。这种判断长期以来依赖于基于规则的评估，但这类评估难以与人类意图保持一致，且当应用程序更新或在线内容变化时会失效。现有的基于模型的评判方法试图解决这些问题，但在性能上仍与基于规则的评估存在差距。我们提出\textbf{SeekJudge}框架，其中四个角色专用的智能体——Condense、Ground、Seek和Analyze——通过沿轨迹的Seek--Analyze循环达成裁决。一个基于种子校准的蒸馏流程训练一个专门的90亿参数模型，作为所有四个智能体共享的骨干网络。在留存的强化学习测试目标的下游成功率上衡量，SeekJudge是首个在实际在线强化学习中达到或超越原生基于规则监督的基于模型的奖励方法。除准确性外，SeekJudge提供步骤级判断，运行成本远低于闭源大模型，且每次调用的上下文规模小，可扩展到更长的轨迹。我们进一步贡献了对奖励服务器的一般性架构改进，加速了强化学习中的评判过程。这些共同使得基于模型的奖励成为计算机使用智能体强化学习中基于规则监督的实用替代方案。

## Abstract
Deciding whether a trajectory actually fulfills its instruction governs how we measure computer-use agents on long-horizon graphical-user-interface tasks and how we train them with reinforcement learning. This judgment has long relied on rule-based evaluation, which struggles to align with human intention and goes stale when an app updates or its online content drifts. Existing model-based judges attempt to address these problems but still leave a performance gap to the rule-based evaluation. We propose the \textbf{SeekJudge} framework, in which four role-specialized agents, a Condense, a Ground, a Seek and an Analyze agent, reach a verdict through a Seek--Analyze loop over the trajectory. A seed-calibrated distillation pipeline trains one specialized $9$B model to serve as the shared backbone for all four agents. Measured by downstream success rate on held-out RL test goals, SeekJudge is the first practical model-based reward to match or surpass native rule-based supervision in online RL. Beyond accuracy, SeekJudge provides step-level judgments, runs far cheaper than a closed-source large model, and keeps a small per-call context that scales to much longer trajectories. We further contribute a general architectural improvement to the reward server that speeds up judging in RL. Together these make model-based reward a practical drop-in for rule-based supervision in CUA reinforcement learning.

### 论文提出的方法论
- **核心思想**：将长轨迹评判任务分解为两个子任务——**定位**（找到含决定性证据的截图）和**提取**（高保真地读取决定性细节）。通过解耦这两个过程，避免在单一前向传播中堆砌过多图像导致的证据稀释和模型幻觉。
- **SeekJudge 框架关键设计（四角色模型）**：
  - **Condense Agent（冷凝）**：接收每步前后两张截图，将整条轨迹压缩为紧凑的文本状态转移描述时间线，解决图像上下文过长的问题。
  - **Ground Agent（落地）**：接收动作后的单张截图及原始操作，识别并描述操作实际点击/作用的界面元素。
  - **Seek Agent（探索，控制器）**：读取冷凝后的时间线，内置状态机。它通过一个循环判断现有证据是否足以给出最终裁决；若不足，则指定需要检查的具体步骤和图像ID，并向 Analyze Agent 发起一次聚焦提问。
  - **Analyze Agent（分析）**：无状态的工具角色，每次调用仅接收一张截图和 Seek Agent 的一个具体问题，返回精确的文字细节，如“截图中显示的是维多利亚瀑布的酒店预订页”。
  - **最终输出**：除轨迹级二元判断外，还提供**7维轨迹分数**和**9类步骤级标签**（如里程碑、正确决策、错误、无意义等），并由梯度提升回归器 (XGBoost) 将多维分数映射为 RL 训练所需的标量奖励。
- **训练与数据构建（种子校准蒸馏管道）**：
  - **种子阶段**：由人类精细标注少量轨迹。先用一个小型提示搜索调整封闭源模型（DeepSeek V3.2）的评判和探索提示，使其输出对齐人类意图；再用更大规模提示搜索优化其探索描述能力。
  - **训练阶段**：使用调优后的提示，以封闭源大模型（DeepSeek V3.2 + Gemini 3.0 Flash Preview）运行完整的 SeekJudge 管道，记录每一步调用作为蒸馏数据，最终将四个角色微调进一个统一的 **9B 参数骨干模型（SeekJudge-9B）**。
- **奖励服务器效率优化**：
  - **预取重叠**：在 RL 动作执行期间，利用闲置的 GPU 窗口异步运行不依赖后续步骤的操作（如 Condense 和 Ground），仅将最终的短流程（Seek-Analyze）留在训练关键路径上。
  - **无状态客户端**：RL 端以任意顺序流式发送截图和动作，奖励服务器负责重排序和调度，使得 RL 代码侧无需任何修改即可享受异步加速。

### 论文的主要结论与发现
1.  **RL 性能达到新里程碑**：SeekJudge 是首个在在线 RL 测试成功率上**匹配甚至超越原生基于规则监督**的模型奖励。规则奖励的训练指标更高，但泛化性较差，存在过拟合。
2.  **框架解耦是关键**：将定位与提取分离，**证据稀释是限制多图评判器性能的核心因素**，而非总数 Token 长度。SeekJudge 通过“单次调用只看一张图”的设计，有效缓解了该问题。
3.  **成本与效率优势**：与 CUAJudge、OS-Themis 及 Codex 等闭源方案相比，SeekJudge 的**单案例成本最低**，且随着轨迹变长，成本与上下文优势愈发显著（4-6 倍上下文缩减）。
4.  **可扩展性**：得益于较小且平稳的峰值上下文，SeekJudge 可以不经修改地处理远超单次前传限制的**极长轨迹（CUAStepBench-Long）**，而 CUAJudge 等方案的性能则会因关键帧被截断或上下文稀释而逐渐饱和甚至下降。
5.  **奖励粒度影响 RL 效果**：提供连续分数与步骤级反馈的**密集奖励信号**优于最终态的布尔奖励，这为 RL 优化提供了更平滑的梯度。

### 优点
- **根本性问题解决**：没有停留在简单的模型替换，而是深入剖析了“证据稀释”这一根本机制，并通过“定位-提取”解耦的框架创新性地解决了它。
- **系统性的实用性考量**：不仅追求精度，更将**成本、延迟、可扩展性**作为核心设计目标。异步奖励服务器等工程优化，使得大模型评判器真正变得可落地。
- **评测与数据贡献**：构建的 **CUAStepBench** 是首个跨平台、轨迹级与步骤级双重人工标注的基准，填补了领域空白，为后续研究提供了高价值的工具。
- **严谨的实验设计**：推理链清晰，从离线噪声分析 -> 框架能力对比 -> 在线 RL 实战 -> 效率分析 -> 受限场景测试，论证层层递进且相互印证。

### 不足与局限
- **平台覆盖的局限性**：虽然 CUAStepBench 覆盖了多个操作系统，但 RL 实验中测试的应用领域（Chrome、Impress、OS）仍相对特定，未在更广泛的真实世界应用（如电商、复杂网页应用）上进行 RL 验证。
- **对动作执行的依赖性**：框架高度依赖 `Ground Agent` 将屏幕坐标映射为界面元素的功能。当模型执行了不改变界面的操作（如无效点击）或应用程序界面元素极度动态时，其准确度可能会受到挑战。
- **数据蒸馏的上限**：模型的性能本质上仍受其教师模型（强闭源大模型）能力的掣肘。虽然成本降低了，但处理更深层视觉逻辑或复杂目标模糊性的能力，可能无法超越最强模型的上限。
- **步骤级奖励在 RL 中的利用**：论文虽然生成了步骤级标签，但在 RL 训练中仍将其聚合为了轨迹级的塑造性奖励，并未探索更为先进的“逐步骤优势估计”，其潜力未在全流程中得到最大化发挥。
